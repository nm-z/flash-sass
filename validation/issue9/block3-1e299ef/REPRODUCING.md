# Reproducing the recorded block check

The original machine-specific runner source has been removed from this PR tip to keep Python out of the change. The original `IDENTITIES.json` remains an immutable record of that capture, including the historical runner hash. The command arrays, environment, expected and actual exit codes, GPU inventory and raw outputs remain in this directory. `ready.json` records that historical fixture's readiness for a GPU run; it is not the current PR's review status.

To repeat the original measurement, build its recorded source revision `1e299ef5e169ed9a88f2f6c8d0241831ab688f72` and use the command arrays and environment in `gpu-results.json`. A run of a newer executable needs a new identity and result record. Before GPU work, acquire `/tmp/flash-sass-engine-validation.lock`, inspect `nvidia-smi` and `ps`, and wait until the required dies have adequate free memory and no competing execution. Release the lock when the run ends. Keep existing holders and the resident engine intact; do not stop, park, restart or reconfigure them to make a test fit. Reproduction requires the recorded real tensor cache, holder manifests and CUDA/MaxAs build.

Each KV placement has one positive case and selection/layer fault-injection controls. The runs used actual block-3 weights, budget 1 and nine sequential synthetic-stream positions. IDs 10..18 were supplied, but the `-` flags enabled neither an embedding lookup nor an output head. The reduced budget reached block exclusion. These logs do not establish embedding/head correctness, 48-block scalar/logit agreement, or production-budget long-context integration. Those integration requirements remain in issue #9. Independent checkpoint quality and natural-language recall are separate from the instruction-order parity contract; see issue #22.
