# GPUQ evidence helpers

These C helpers are specific to the issue-16 validation run. They were compiled through DSH, copied to Archy tmpfs, and invoked only with `ssh archy gpuq run -- ...`. The helpers do not implement product behavior.

- `issue16_matrix_launcher.c` runs the `run_qsa_gather_pair.nu` matrix with `~/.local/bin/nu` (or `NU_BIN`); its `captured` cases use `write_qsa_gather_ids.nu` to generate the same sorted little-endian fixture rows. It puts a compressed raw-results bundle into GPUQ and removes its temporary tmpfs directory.
- `issue16_capture_launcher.c` runs the verified `qsa_test idxfull` capture, checks the sorted ID row, pairs captured and per-token cases across host/VRAM, and uploads the raw results.
- `issue16_profile_launcher.c` runs one separate nvprof metric group for each paired host/VRAM job, checks the outputs, and uploads the logs and counter CSVs. On Archy, unprivileged nvprof returned `ERR_NVGPUCTRPERM`; the successful helper invokes nvprof through `sudo -n` inside the GPUQ-locked process. It does not change driver settings.
- `production_prompt_ids.c` renders a single user message through the tokenizer GGUF's own Jinja chat template, with `add_generation_prompt=true`, then uses the repository tokenizer to write the exact prompt IDs. The issue-16 prompt IDs are produced from a metadata-only range prefix of the pinned Q2_0 GGUF; the prefix hash and source revision are recorded in `production-prompt-tokenizer.md`.
- `issue16_production_launcher.c` runs those IDs plus one greedily generated token through all 48 model blocks using `model_test` and the live holder manifests, captures the production `OP_IDXSEL` output from attention block 47 at position 2052, validates the 512 sorted IDs against 513 candidate blocks, then runs paired `qsa_gather_bench` arms at `nv=513`, `tail=1`, `position=2052`, host placement 0 and 1. Each gather arm checks the gathered K/V values against the C reference before timing. The launcher uploads the exact prompt, rendered prompt, token IDs, selection row, holder manifests, binaries, cubin, logs, JSON/CSV results and hashes through `gpuq put`; its scratch files live in `/dev/shm` and are removed after upload.

The production model run uses the full real tokenizer/chat-template prompt, model embeddings, weights from the existing six-die holders, the real PLE GGUF shard, and the production QSA persistent program. Its scalar whole-model twin is disabled because the issue-10 fullcache lineage is unavailable; the evidence does not claim a bit-exact whole-model comparison. The captured IDs come from the actual model's `OP_IDXSEL` output and are independently range/ordering checked. The paired gather arms use the same captured IDs and finite position/channel-signature K/V fixture, with each output compared against the C gather reference. This validates the benchmark with a real production selection without treating the synthetic K/V cache as model data.

Build the C launchers and test binary with DSH, then copy only those binaries, `run_qsa_gather_pair.nu`, `write_qsa_gather_ids.nu`, `die.cubin`, `production-prompt.txt`, the rendered prompt, the token-ID list, and tokenizer provenance to a task-local directory under `/dev/shm` on Archy. The Nu executable is already installed at `~/.local/bin/nu`. The production launcher requires the pretokenized files, checks the token count and ID range, and does not open the NFS tokenizer shard. `tokenizer-source.txt` identifies the pinned GGUF metadata prefix used to produce them. Run the launcher only through `ssh archy gpuq run -- ...` after the shared queue is available. Its arguments are the local PLE shard, holder manifests for dies 0 through 5, and the full source commit. The launcher checks the build revision embedded in `qsa_gather_bench` before accepting the pair.

The helpers use the `/dev/shm/fs16-64cf` paths and the M60 UUID recorded in the manifests. Their output manifests, exact binary/cubin hashes, GPUQ job identities, and raw results are in the parent directory.
