# Production prompt tokenizer provenance

The 2,697 prompt-token IDs and rendered chat text for the issue-16 production capture were generated by the repository's `tok.c` and `jinja.c` from the exact Q2_0 model GGUF tokenizer metadata, using a 64 MiB HTTP range prefix of this pinned source:

- Repository: `ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF`
- Revision: `1c04b8102ca5346f1faf4d9914503e378d713021`
- File: `Q2_0/Qwen3.8-Flash-Next-GSQ-RCO-Q2_0-00001-of-00002.gguf`
- Full source-file SHA-256: `69820c02ec7d0b45ef2ebb19d6620299db749fe2aded7f39f93c6b88b199b720`
- Retrieved byte range: `0-67108863` (HTTP 206, exactly 67,108,864 bytes)
- Prefix SHA-256: `db705ca4fb85ea5c8102285dc749646c4123a5412a4b023003f86aa96a25d054`

The prefix is GGUF v3; `gguf_open` parsed the metadata and tensor table, and `tok_load` accepted `tokenizer.ggml.model=gpt2`, `tokenizer.ggml.pre=qwen35`, the 248,320-token vocabulary, the merges, and `tokenizer.chat_template`. `production_prompt_ids` rendered the committed `production-prompt.txt` with the GGUF chat template and `add_generation_prompt=true`, then wrote the 2,697 IDs. The ranged prefix contains metadata used for tokenization; it is not used as model weights. The model run uses the six live holder manifests and local PLE shard on Archy.
